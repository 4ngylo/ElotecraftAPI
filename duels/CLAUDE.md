# duels module

`Duels` wires everything (the `JavaPlugin` only starts and stops it, so tests run it on a mock plugin). Packages: `arena` (YAML registry; arenas have categories that kits pick from, an optional center and build limit; `ArenaInstances` lends arenas to duels, one at a time, puts back blocks changed by build kits from `ArenaChanges`, and rebuilds arenas a crash left changed from `ArenaTemplate` snapshots (`.blocks`); while an arena is busy it leases a copy from `ArenaPool`, which pastes the arena's WorldEdit snapshot (`arenas/<arena>.schem`, saved with the `.blocks` one by `/duels arena snapshot`) on a grid in the void `ArenaWorld`. Copies live only in memory, are `Arena` records with the arena's name and `Arena.copy` set (so history, rematches and placeholders see the arena), and the `ArenaInstance` of a fresh copy completes `ready()` once pasted: `MatchManager.start` keeps the fighters in `STARTING` until both their snapshot save and the paste are done, so callers stay synchronous. `ArenaPool.maintain` (from `ArenaInstances.tick`, every second) pastes one ahead while an arena has fewer than `arenas.pool.warm` free places (the arena itself counts while free) and clears copies free for `idle-timeout` beyond those or no longer matching their arena record or snapshot; pasted boxes are recorded in arenas.yml `pool-boxes` and cleared at the next start. Old `copy-of` entries from `/duels arena pregen` are dropped and their boxes cleared by `ArenaRegistry`), `kit` (YAML registry; `KitRule` per-kit game rules enforced in `CombatListener`, flags falling back to `Settings` or true, numbers up to the rule's `max()` (`pearl-cooldown` in seconds, `hits-to-win` counted per victim in `Match.hit`, only for hits outside the victim's invulnerability: Paper fires the damage event again for a harder hit inside it, and for every hit once a knockback-only kit zeroes the damage); `rounds-to-win` makes a duel a series: a knockout in `MatchManager.knockOut` wins the round, `ROUND_OVER` waits `round-delay-seconds`, then `ArenaInstances.resetRound` puts the arena back and `teleportFighters`/`beginCountdown` run again on the same timer; `Match.betweenRounds` turns a quit or `/duel leave` into a loss; combo hit delay and pearl cooldown are undone by `PlayerSnapshot`), `state` (`PlayerSnapshot` saved to the database before a duel touches a player, restored after; leftovers restored at login; a restore deletes the snapshot when it starts the async teleport back, so `SnapshotStore.finishReturn` (called on quit) teleports a player still on the way at once, or they would be saved in the arena), `stats` (wins and streaks in `duels_stats`; Elo ratings per kit in `duels_ratings`, written as deltas, a player's first row in a kit seeded by `INSERT ... SELECT` from the frozen `duels_stats.elo` (the rating before per-kit ratings, kept as `PlayerStats.legacyElo`); the overall rating is the average over existing kits; `Divisions` from `ranked.divisions`; both tables are created in one first transaction because logins read them with `runBlocking` without waiting for `ready()`; `peak` per kit rating, set by `RECORD_RATING` before the rating changes (MySQL applies SET left to right) and added to old tables by `createTables`; `Seasons`: `duels_seasons` archive, one transaction to archive and reset ratings (`DELETE FROM duels_ratings` and `duels_stats.elo` back to the start), the season running is one past the last archived, rewards paid by `SeasonAdminCommand` through the public `Rewards`; `DailyRanked` (in `match`) counts ranked duels per day in the player's PDC; `Bets` (in `match`): stakes taken through `VaultEconomy` when a bet challenge is accepted (`RequestManager.accept`, which holds them for the match or refunds a duel that never started) and stored in `duels_bets`, settled from `MatchManager.onFinish` by `Match.winnerTeams` (no winner refunds), stakes still stored at start refunded from `Bets.tick` once an economy is there, so shutdown only forgets them; tests fake Vault with a `Proxy` economy and a mock plugin named Vault; `MatchHistory`: finished duels in `duels_history`, one row per player keyed `(uuid, ended_at)`, looked up by name through `duels_stats`), `match` (`MatchManager` lifecycle of fights between teams, with what a result changes (stats, Elo, history, rewards, rematches, kept inventories) in `MatchResults`, a duel being two teams of one: knocked-out fighters watch until one team is left; only `Type.DUEL` counts stats, Elo, rewards and rematches, `RequestManager`, `QueueManager` with an unranked FIFO queue and a ranked rating-range queue per kit, `Rewards`; only ranked-queue duels move ratings; `FightStats` counts hits, combos and health potions per match, and `Match.recordFinal` keeps each fighter as they left the fight (before death drops) for `/duel inventory` (kept in `FightResults`), linked from the names in a duel's result line, and for other fights from a line sent in `finish`; menus do not open while players are still in the match, so `/duel inventory` refuses until then), `party` (`PartyManager`: parties of online players with a leader, invites that expire, leader handover on leave or quit; `PartyFights`: split, FFA and party-vs-party challenges as `Match.Type.PARTY`; FFA spawns come from `ArenaInstance.spawnFor`), `listener` (combat rules, protections, build rules and block recording, sessions; `PlayerPortalEvent` has its own handler list, so `ProtectionListener.onTeleport` never sees portals and `onPortal`/`onEntityPortal`/`onPortalCreate` block them in duels and the arenas world), `menu` (`KitAdminMenu` and `ArenaAdminMenu` are `/duels kit [kit]` and `/duels arena [arena]`: their buttons run the subcommands with `performCommand` and ask text with `MenuLayout.ask` (`ChatInput`), so setup logic stays in `AdminCommand` (arenas) and `KitAdminCommand` (kits); tests click with `Menu.button(slot)` and register `InputListener` for chat answers), `event` (`EventManager`: player-hosted events gathering players, then one `Match.Type.EVENT` fight with `Match.Options` (winner count, spectators, border, host); waiting players are `MatchManager.waitingElsewhere`: busy for queues, requests and spectating but not `isRestricted`, so the listeners leave them alone; `FightBorder` draws a per-player world border and applies its damage itself, MockBukkit cannot show it so only its math is tested; `EventMenu` holds the event menus; tournament and sumo modes run a `Tournament`: 1v1 `EVENT` fights with `Match.Options.bracket` (no reward or broadcast per fight), driven by `MatchManager.onFinish` and `Match.winnerTeams`/`endReason`, its players `isWaiting` between fights (`EventManager.mayWatch` lets them spectate its fights) and each fight starting only once both are back (`SnapshotStore.isReturning`); a fight without a winner goes back to `pending` up to `events.tournament-replays` times per round, then a coin flip; mode `DOUBLE` gives each player 2 lives (`Tournament.losses`), and `newRound` sorts the shuffled players by losses before pairing, so a reset final needs no special case; `events.schedule` hosts events with `HostedEvent.SERVER` as host, which does not join, from `runSchedule`), `hud` (`LobbyItems`: optional lobby hotbar items, PDC-tagged, synced to each player's state from `Duels.tick()`, never touching untagged items; the lobby-world rule is `Settings.isLobby`; `DuelsSidebar`: the optional sidebar, refreshed from `Duels.tick()` with cached stats and a leaderboard read every minute, `modeLine` adding a goals or beds line under the first line of a mode fight; MockBukkit cannot show sidebars, so tests turn `sidebar.match` off and check `layoutFor`), `command`, `PingRange` (root package: the highest opponent ping a player takes, cycled in `OptionsMenu`, checked in both `QueueManager` pairings), `LobbyVisibility` (in `hud`: `LOBBY_PLAYERS` off hides everyone but the party in `lobby-items.worlds`, only undoing its own hides), `Match.watchableBy` (spectating rules for `/duel spectate` and `SpectateMenu`; a player `Match.isWatching` (spectator or knocked out) gets `SpectateMenu.openFighters` and `/duel spectate <fighter>` teleports them in their fight; `InMatchMenu`s (the fighter menu, the custom kit items menu) are the only inventories `ProtectionListener` lets players in a match or the kit editor open; `hud/WatchItem` keeps a PDC-tagged item in watchers' inventory slot `spectate-fighters.item.slot`, synced from `Duels.tick()`, whose click opens it: spectator mode has no hotbar, but its inventory opens and clicks reach the server (checked with mineflayer, `smoke.js fighterMenu`; a real client is not checked)), kit `effects` and `Kit.applyStatus` (max health as the `PlayerSnapshot.KIT_MAX_HEALTH` attribute modifier, which `clearKitRules` removes first on every reset and restore, effects and the saturation effect, given in `beginCountdown`), kit modes (`Kit.Mode` BRIDGE and BED_FIGHT, build kits only, played by fights of two sides (`Match.mode()`): `MatchManager.knockOut` calls `respawn` while `Match.respawns(team)` (bridge always, bed fight while the side's bed stands), which re-equips at once and teleports a tick later (`TeleportCause.UNKNOWN`: Essentials' `teleport-invulnerability` blocks hitting and being hit for seconds after a PLUGIN or COMMAND teleport); a real death respawns at the spawn (`CombatListener.onRespawn`) and `respawned` equips; `CombatListener.onMove` scores a bridge goal (`Match.scoresAt`: the goal radius, or an `END_PORTAL` block nearer the other goal; the only place goals are counted, `ProtectionListener.onPortal` just cancels portals silently), and `MatchManager.score` makes the scorer a spectator teleported a tick later to `ArenaInstance.middle()`, then wins a round through `roundOver` (the next `beginCountdown` equips them back to survival), `nextRound` skips `resetRound` for bridge; `GoalHolograms` (`modes.bridge.goal-hologram`, off in tests: MockBukkit cannot spawn displays) from the first `beginCountdown` to `finish`; the bridge golden apple heals fully with `LivingEntity.heal` in `CombatListener.onGoldenApple` (MockBukkit has no `heal`, so its test is reported as skipped); `kit/TeamColors` dyes side 1 red and side 2 blue in `MatchManager.equip` for mode kits; kit rule `arena-bounds` lets fighters leave the box sideways; `BuildListener.breaksBed` lets an enemy break a side's bed (recorded in `ArenaChanges`, put back with the arena) and `bridgeProtects` keeps blocks away from spawns and goals; the points are `Arena.ModePoints`, set with `/duels arena setgoal|setbed` and offset into pool copies, and `Kit.accepts` refuses arenas without them), custom kits (`kit/CustomKits`: built in `KitEditor` sessions with a `customSlot`, stored by `KitLayouts.store` under `custom:<slot>`, a `Kit` named `Kit.CUSTOM` (reserved, so `KitRegistry.current` returns it as is while admin kits are read again by name: requests, party challenges and rematches keep the `Kit`); `DuelCommand`/`PartyCommand` resolve `custom[:slot]` with `CustomKits.resolve`, `KitMenu.open` takes them as extra kits; never queues, events or bets; `CustomKitMenu` is the slot menu and the items menu, an `InMatchMenu` like the fighter menu), public parties and party chat in `PartyManager` with `PartyMenu` running `/party` subcommands (`/pc` alone toggles chat mode: `PartyManager.onChat` cancels the `AsyncChatEvent` off the main thread and sends to the party on it; the mode is dropped when the player leaves the party), `PlayerOptions` (root package: per-player on/off flags in the player's PDC, all on by default, switched in `OptionsMenu` (`/duel options`) or by `/duel toggle <option>` (usage without one); `REQUESTS` keeps the `requests-off` key of `/duel toggle`; checked in `RequestManager`, `PartyManager.invite`, `DuelsSidebar.tick` and `Effects.play`), `Cosmetics` (root package: kill effects and kill messages from config.yml `cosmetics`, a player's pick in their PDC; `MatchManager.knockOut` credits an `ELIMINATED` knockout to the last opponent who hit the victim (`FightStats.lastHitBy`) and `MatchDisplay.knockedOut` plays the effect and sends the message; MockBukkit has no `strikeLightningEffect`, so tests use a sound effect), `LeaderboardHolograms` (in `hud`: `/duels hologram` boards in `holograms.yml`, text from the `/duel top` messages read every minute (`holograms.lines` players), spawned from `Duels.tick()` once their chunk is loaded; MockBukkit cannot spawn holograms, so tests keep boards in a world that does not exist or check them before the next second's tick), the match sidebar's `sidebar.health-below-name` (API `Sidebar.healthBelowName`, so players with the sidebar off don't see it; a DUMMY objective that `DuelsSidebar` sets with `Sidebar.updateHealth` a tick after damage or healing events and every second, since `Criteria.HEALTH` scores are read-only on Paper and only sent once health changes), `hook` (Vault and PlaceholderAPI behind nested classes so they stay optional; WorldEdit is required (`depend: WorldEdit`, which FAWE provides): `WorldEditHook` is the interface for copying, saving, loading, pasting and clearing boxes and the player's selection, `WorldEditBridge` its implementation on the real API, off the main thread on FAWE). FAWE 2.15.0 is a `provided` dependency with its transitive libraries excluded; MockBukkit runs no WorldEdit, so tests start `Duels.start(plugin, worldEdit)` with `FakeWorldEdit` (Bukkit block copies, pastes that can be held or failed). Main code compiles with `-Xlint:deprecation -Werror`. User docs in `duels/README.md`.
