# duels module

`Duels` wires everything (the `JavaPlugin` only starts and stops it, so tests run it on a mock plugin). Packages: `arena` (YAML registry; `ArenaInstances` lends arenas to duels, puts back blocks changed by build kits from `ArenaChanges`, rebuilds arenas a crash left changed from `ArenaTemplate` snapshots, and copies arenas in AdvancedSlimePaper worlds once per duel), `kit` (YAML registry), `state` (`PlayerSnapshot` saved to the database before a duel touches a player, restored after; leftovers restored at login), `stats`, `match` (`MatchManager` lifecycle, `RequestManager`, `QueueManager`, `Rewards`), `listener` (combat rules, protections, build rules and block recording, sessions), `menu`, `command`, `hook` (Vault, PlaceholderAPI and AdvancedSlimePaper, each behind a nested class so they stay optional). ASP is a server fork: `com.infernalsuite.asp:api:4.1.0` is the last release compiled for Java 21; tests run against `hook/FakeSlimeApi`, registered in `src/test/resources/META-INF/services`, so every duels test sees ASP as present. Main code compiles with `-Xlint:deprecation -Werror`. User docs in `duels/README.md`.
