# duels module

`Duels` wires everything (the `JavaPlugin` only starts and stops it, so tests run it on a mock plugin). Packages: `arena` (YAML registry; arenas have categories that kits pick from, an optional center and build limit; `ArenaInstances` lends arenas to duels, one at a time, puts back blocks changed by build kits from `ArenaChanges`, and rebuilds arenas a crash left changed from `ArenaTemplate` snapshots; `ArenaPregen` pastes read-only copies of an arena's snapshot on a grid in the void `ArenaWorld`, and a copy is rebuilt from its source's snapshot at its offset), `kit` (YAML registry; `KitRule` per-kit game rules enforced in `CombatListener`, flags falling back to `Settings` or true, `pearl-cooldown` in seconds; combo hit delay and pearl cooldown are undone by `PlayerSnapshot`), `state` (`PlayerSnapshot` saved to the database before a duel touches a player, restored after; leftovers restored at login), `stats` (wins, streaks and one global Elo rating in `duels_stats`; rating changes are written as deltas), `match` (`MatchManager` lifecycle of fights between teams, a duel being two teams of one: knocked-out fighters watch until one team is left; only `Type.DUEL` counts stats, Elo, rewards and rematches, `RequestManager`, `QueueManager` with an unranked FIFO queue and a ranked rating-range queue per kit, `Rewards`; only ranked-queue duels move ratings), `party` (`PartyManager`: parties of online players with a leader, invites that expire, leader handover on leave or quit; `PartyFights`: split, FFA and party-vs-party challenges as `Match.Type.PARTY`; FFA spawns come from `ArenaInstance.spawnFor`), `listener` (combat rules, protections, build rules and block recording, sessions), `menu` (`KitAdminMenu` and `ArenaAdminMenu` are `/duels kit [kit]` and `/duels arena [arena]`: their buttons run the subcommands with `performCommand` and ask text with `MenuLayout.ask` (`ChatInput`), so setup logic stays in `AdminCommand` (arenas) and `KitAdminCommand` (kits); tests click with `Menu.button(slot)` and register `InputListener` for chat answers), `event` (`EventManager`: player-hosted events gathering players, then one `Match.Type.EVENT` fight with `Match.Options` (winner count, spectators, border, host); waiting players are `MatchManager.waitingElsewhere`: busy for queues, requests and spectating but not `isRestricted`, so the listeners leave them alone; `FightBorder` draws a per-player world border and applies its damage itself, MockBukkit cannot show it so only its math is tested; `EventMenu` holds the event menus), `hud` (`DuelsSidebar`: the optional sidebar, refreshed from `Duels.tick()` with cached stats and a leaderboard read every minute; MockBukkit cannot show sidebars, so tests turn `sidebar.match` off and check `layoutFor`), `command`, `hook` (Vault, PlaceholderAPI and FastAsyncWorldEdit/WorldEdit, each behind a nested class so they stay optional; `WorldEditHook` pastes pregen copies with block data and imports schematics, off the main thread on FAWE). FAWE 2.15.0 is a `provided` dependency with its transitive libraries excluded; MockBukkit runs no WorldEdit, so tests cover the snapshot path. Main code compiles with `-Xlint:deprecation -Werror`. User docs in `duels/README.md`.
